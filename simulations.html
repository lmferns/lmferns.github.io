01

Field Service Simulation

  • Articulate Storyline 360
  • Software simulation
14-day sprintfrom SME screen captures to a scored, SCORM-ready simulation

Challenge

Field service engineers were opening a lot of support tickets because they got lost in the service software or troubleshot it the wrong way. The existing training was a passive tour of the interface, so it never gave them any practice. I had two weeks to build a hands-on simulation that would cut down those mistakes.

What I did

  • Built a Storyline 360 software simulation from SME screen captures and technical documentation.
  • Added clickable menus and decision points with realistic wrong choices, plus immediate feedback, so engineers could make mistakes safely before they reached a customer site.
  • Handled the full build, from gathering assets to setting up the scoring, inside a 14-day sprint.
  • Built a mastery exam into the simulation to confirm engineers could launch, navigate and customize the software on their own.

Result

  • Early feedback after rollout pointed to fewer tickets about navigation and software misuse.
  • Engineers consistently passed the built-in exam.
  • The SCORM package can be updated quickly as the software interface changes.
02

Interactive Troubleshooting Decision Tree

  • Articulate Storyline 360
  • Branching logic
  • Variables & triggers
30+ pathsdiagnostic branches in one guided tool

Challenge

Engineers troubleshooting Android and iOS-based medical hardware were working from static documentation that was hard to follow under pressure. I built a digital decision tree that walks them through specific failures (cables, transducers, network) to the right fix, without digging through a manual.

What I did

  • Built a branching structure in Storyline 360 with more than 30 diagnostic paths.
  • Designed a custom menu that tracks progress, with green borders marking completed sections and correct paths.
  • Used variables and triggers so engineers could jump back to the main page at any point without losing their place.
  • Rebuilt SME diagrams into an interface that mirrors the real equipment workflow.

Result

  • A dense diagnostic manual became a tool engineers can actually click through.
  • Each step has to be worked through, so engineers can no longer skip ahead the way they could with a static document.
  • New hardware versions or failure codes can be added without rebuilding the logic.
03

Multi-Device Software Onboarding

  • Rise 360
  • Storyline 360
  • Camtasia
  • Vyond
30% increasein learner participation

Challenge

The old training for the field service software only worked on a desktop, but engineers in the field use phones and tablets. They needed training that worked on any device and combined the big-picture concepts with hands-on software practice.

What I did

  • Built the course in Rise 360 so it works on desktop, tablet and phone.
  • Embedded Storyline blocks inside Rise so engineers could practice real tasks in a software sandbox.
  • Added Camtasia walkthroughs and Vyond animations to show how the hardware and software work together.
  • Built every block to WCAG accessibility standards and published it as SCORM for LMS tracking.

Result

  • After the switch to interactive Rise blocks, escalation tickets about software navigation went down.
  • Learner participation rose 30%.
  • The course was built and reviewed inside our ISO 9001 quality process.
